Case Study: ARM-Based Infotainment Prototype

A “De-Googled” Android cockpit UI prototype built for OEM constraints and rugged environments.

Problem

Standard Android Automotive (AAOS) environments can be restrictive—limited APIs, dependency on Google Play Services, and friction integrating third-party mapping/media stacks.

Architecture

Built on Raspberry Pi 4/5 (ARM). Development workflow using Android Studio + VS Code, with a focus on integration speed and stable runtime behavior.

Optimization

Optimized for ARM v8-A with high-resolution rendering and minimal latency—targeting smooth UI transitions and reliable performance on low-cost ARM hardware.

UX Innovation: “Max Touch Mode”

A simplified interaction model with expanded hit-targets designed for high-vibration, off-road, and rugged use—better usability with gloves and motion.

Integrations

Deep integration for third-party services like Spotify and OsmAnd+ without relying on Google Play Services, reducing dependency on restricted automotive APIs.

Maps API for Vehicles

Solved a vehicle-specific Google Maps API integration problem by designing around constraints, ensuring navigation remains reliable and usable for automotive contexts.
